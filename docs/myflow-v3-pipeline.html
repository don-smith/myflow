MyFlow v3 — Artifact-Led 5-Stage Workflow

Right-sized, resumable AI-assisted development: Scope → Plan → Implement → Verify → Close.

One canonical orchestrator per stage. A stage artifact records the decision or evidence that the next stage needs; it does not replace upstream records. The workflow adapts to risk: a truly trivial, uninterrupted change may stay in conversation, while durable work uses a workstream.

collaborate: Scope & Plan autonomous: Implement evidence-led: Verify collaborate: Close
Before a repository when needed — onboard

Resolve the repository map and record repository-specific instructions, checks, documentation, retention, and delivery policy. Onboarding is a repository capability, not a sixth workstream stage.

1. Scope — scope

collaboratively establish the outcome and right-sized path

Set intent, non-goals, observable acceptance criteria, constraints, risk, workflow depth, and the next specialist or planning action. Scope establishes the workstream ID and offers the repository's permitted worktree or trunk path.

Optional specialists: discover, research, grill-with-docs, prototype, domain-modeling, architecture-review, improve-codebase-architecture, wayfinder, wizard
Output: workstream.md and an alignment artifact; focused research, when selected, is supporting evidence.

Default paths: .myflow/workstreams/<workstream-id>/workstream.md, scope/, and (when used) research/.

▼ ready Scope artifact and selected evidence

2. Plan — plan

collaboratively make implementation executable

Produce the accepted implementation authority: phases, a verification map, commit boundaries, manual checks, delivery constraints, and rehydration information. Every executable plan declares its design disposition.

Design when justified: design resolves material structural decisions. Use tdd, codebase-design, architecture-review, domain-modeling, or prototype only when the work needs them.
Output: a lightweight or full executable plan; a standalone design artifact only for structural design.

Default paths: plan/; structural work also uses design/. Design dispositions: locked into existing architecture · localized design · structural design required.

▼ accepted, ready plan — start a fresh implementation session

3. Implement — implement

autonomously execute accepted plan phases

Work phase by phase against the plan's test-first seam and required checks. After each green phase, create one atomic phase commit with commit; update the implementation checkpoint with evidence, commit hash, deviations, and outstanding manual verification.

Use as needed: tdd for an uncovered behavior or design gap; diagnosing-bugs for evidence-first failure investigation; resolving-merge-conflicts for an in-progress Git recovery.
Output: completed plan state or implementation checkpoint, green phase commits, and the working tree.

Handoff: the plan/checkpoint and phase commits become Verify's input. Code review is not an implementation gate.

▼ implementation evidence and final green phase commit

4. Verify — validate

independently validate execution against the plan

Run the plan's automated checks, inspect completed phases and acceptance-criterion coverage, and invoke code-review against the implementation range and accepted plan. Prepare a manual-verification brief only for human-facing, external, or non-automatable checks.

Output: a validation report with verdict, automated evidence, separate Standards and Spec review evidence, deviations, exclusions, and any manual brief.
Correction loops: implementation defect → Implement; incorrect plan → Plan; changed architecture → Design; changed outcome or acceptance criteria → Scope.

Default path: .myflow/workstreams/<workstream-id>/verify/. A passing report hands off to Close; a failing report names its owning corrective stage.

▼ passing validation report and any required human evidence

5. Close — close

collaboratively deliver, preserve continuity, and leave no unowned follow-up

Use Verify evidence and repository policy to choose only applicable documentation, status, learning, retrospective, changelog, and delivery actions. Record every unresolved follow-up with a destination; do not force ceremonial closeout work.

Optional closeout skills: capturing-learnings, writing-retros, changelog, and commit for a distinct, developer-approved final closeout commit.
Output: repository-specific closeout updates and, when decisions, manual evidence, or follow-ups must persist, a resumable closeout summary.

Default path: .myflow/workstreams/<workstream-id>/close/. Delivery (push, merge, PR, retain branch, or defer) is recorded with the developer rather than inferred.

Workstream artifact layout

New durable work uses one local workstream directory. The resolver-selected repository map can override these defaults; existing flat .myflow/artifacts/ directories are legacy and are not bulk-migrated.

Cross-cutting practices

create-handoff / resume-handoff

Artifacts are the normal stage handoff. Use this pair only for a mid-stage or mid-phase interruption; the handoff points back to the authoritative artifact.

epiphany-tabling

Preserve an out-of-scope observation without expanding the current work. Route it at the next checkpoint to a new Scope, mapped backlog, learning artifact, or deliberate drop.

capturing-learnings

At a useful artifact checkpoint, decide whether evidence merits a skill, runbook, repository record, backlog item, or no preservation.

Fresh stage boundaries

A new session resolves the repository map, then reads workstream.md, the authoritative artifact, linked evidence, and current Git state.

Repository policy wins

The repository map governs paths, instructions, checks, documentation, retention, and delivery. MyFlow defaults are fallbacks, not local policy.

Correction ownership

Return a finding to the stage that owns its decision; re-run downstream verification after the correction rather than masking a change in a later stage.
